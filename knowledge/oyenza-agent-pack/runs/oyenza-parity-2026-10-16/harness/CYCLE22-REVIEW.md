## Source findings

1. `src/map/damageMaterial.ts:4-25` puts a per-triangle corner attribute on non-indexed geometry and uses barycentric interpolation plus fragment derivatives to mix the grid into the opaque surface's outgoing color. The grid has no second coplanar mesh, transparency depth pass, physical displacement or depth-test bypass. `DamageLayer.ts:66-73` correctly expands the indexed physical triangles before assigning those independent corner attributes; original coordinates and smooth normals are copied, and the temporary indexed geometry is disposed. The cavity sampler/dimensions and world transform are unchanged. Non-indexed expansion increases vertex/attribute storage versus the old solid geometry; reduced draw count alone does not establish a performance improvement.
2. Installed Three is0.170.0. Its `ShaderLib/meshphysical.glsl.js:40,221` contains the exact `begin_vertex` and `opaque_fragment` injection points. The latter writes outgoingLight in the installed fragment chunk. `fwidth` is available in the required WebGL2 context. The helper adds fixed uniform/varying names without requiring per-report shader variants. Three's default `Material.customProgramCacheKey()` includes onBeforeCompile source; there is no dynamic closure setting requiring a separate cache key here. No incompatible r170 hook was found. This assessment is tied to the installed version, not a promise for future upgrades.
3. `DamageLayer.ts:103,106` issues actual DEPTH_RANGE queries only when verifyDepth is enabled. Default false leaves diagnostic values null, which must not be reported as measured equality. The prototype explicitly enables verifyDepth (`tests/geometry/prototype.html:12`), and `geometry.browser.spec.ts:20-25` requires arrays of two finite numbers before equality. This preserves the depth oracle and prevents null==null from becoming a pass. No fabricated cached depth range is supplied.
4. `DamageLayer.ts:120-129` still disposes owned geometry/material sets and renderer wrapper, then clears ownership references. The new corner buffer is an attribute of the owned bowl geometry and is released with it. The old separate wire material/draw is absent; the shared MapLibre context/canvas is not lost/deleted, autoClear remains false, and the z=0 local depth-only aperture is unchanged. No new resource requiring independent disposal was identified. Full total GPU/heap reclamation was not measured by this review.
5. `Map3D.tsx:174` now requests antialias:false. That request changes the whole map context, whereas the material's derivative smoothing addresses the cavity grid. Captured close views support that local visual tradeoff. This review does not establish actual context attributes/SAMPLES, city-wide diagonal building-edge quality, or frame-time benefit; those must come from root's separate context/visual/performance evidence.
