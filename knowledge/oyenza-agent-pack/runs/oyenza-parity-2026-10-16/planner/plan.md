## Five findings

1. **Camera has competing owners.** `src/App.tsx:44-46` stores inspection separately from `src/components/Map3D.tsx:304-309` navigation/orbit state. Map initialization, zoomend, report selection, inspection, search, toggle, reset, Jalanan, and Atas each issue independent camera commands (`Map3D.tsx:317,505,720,734,784,804,828,920,933`). Toggle 2D does not end inspection/orbit. Filtered reports at `App.tsx:82` can exclude `selectedReport`, still passed at line 378. P1 should use one controlled `CameraMode = '2d' | '3d' | 'inspect'` in App, preserve previous navigation mode, stop pending flight/RAF synchronously, and route camera intents through one helper. Remove automatic zoom tilt to keep ordinary 3D pitch 56. Selection/search/CCTV/reset must honor current mode. Explicit inspection is the only transition from 2D to inspect.
2. **Dimensions are presentation values, not consistent geometry.** `Map3D.tsx:91,186-188,691` hardcodes radius 4 m, trench dimensions/heading, and road width 7 m. `DepthInspector3D.tsx:76-77` replaces zero/small values with minimum/default measurements. `src/types.ts:22-42` has width/depth but no length, heading, road width or provenance. P1 adds a small internal adapter: cm / 100, finite-number validation, width > 0, depth >= 0 with zero explicitly representing no depression; missing length/heading/roadWidth remain null and provenance unknown. Do not convert old decorative footprints into physical geometry or change API/DB. D03-D04 labels remain open for P5.
3. **MapLibre 4.7.1 does not give ordinary 2D road layers physical ground depth.** Installed source `node_modules/maplibre-gl/src/render/painter.ts:324-338` collapses eligible 2D depth to one constant layer slot near 1; line rendering uses read-only depth (`draw_line.ts:27`), opaque fill/background may write that slot (`draw_fill.ts:43`, `draw_background.ts:31`). `painter.ts:415` reserves a nearer range for 3D; `draw_custom.ts:33-39` gives a custom 3D layer LEQUAL/read-write in that range. Layers after the first 3D layer use painter ordering with depth disabled by MapLibre. Inference: a below-zero mesh can render over flat road color when ordered correctly; a physical local rim/road occluder still has to be supplied and proven. No render proof was produced by this planner.
4. **Current inspector sampler cannot be copied unchanged.** Its Gaussian is cut at 1.5 radius with nonzero edge, noise changes the physical profile, and contours use a different analytic circle (`DepthInspector3D.tsx:85-99,145-161`). The mesh support differs from reported diameter. P2 should use one compact-support radial sampler whose rim is exactly z=0 and center exactly -depth, then derive surface/wire/contour from that sampler. Do not copy modal background, independent camera/canvas, endless rotation, or `forceContextLoss` cleanup (`DepthInspector3D.tsx:31-45,228-235,274-279`) into shared GL.
5. **Highest P4 deviations are source geometry, map palette/hierarchy, and panel proportion.** Prior map comparison visibly shows arbitrary large rectangular blocks versus continuous source footprints, yellow roads/dense POIs versus neutral white streets, and a wider/heavier left panel. References: `knowledge/video-review-2026-10-16/map-comparison.jpg` top is recording 214801 at 00:12, bottom prior local baseline; current source locations `Map3D.tsx:319,440-455`, `src/services/mockData.ts:186`, `App.tsx:106`. Inspection comparison also shows city blocks dominating the view and a separate modal. These are observed prior visuals, not new screenshot measurements. P4 proposes replacing mock rectangles with verified source footprints, neutral style and zoom-based labels, then compacting the existing panel/controls; no redesign is authorized by this report.

## P2 local aperture hypothesis and falsification

**Recommended first experiment - ordinary depth plus a local depth-only ground annulus.** Draw base 2D road layers first. Insert the custom layer before the first 3D building extrusion, after every 2D road layer that must remain beneath the cavity. Inside the custom scene, render the synthetic z=0 road stage excluding its 0.52 m aperture with `colorWrite=false`, depthTest/depthWrite enabled and ordinary LEQUAL, then render the bowl and visual helpers using ordinary depth. Annulus retains existing road color outside the aperture while supplying physical near-rim occlusion. Bowl stays z<=0. No depth clear, stencil takeover, global depth disable, or raised mesh is needed by this hypothesis. A visible opaque synthetic stage is a simpler P2 fixture variant; it must remain labeled synthetic.

The existing damage fill/line layers are currently appended after building extrusion (`Map3D.tsx:446-480`) and thus can paint over 3D. For the one P2 fixture, hide/exclude its old decorative footprint and put required 2D overlays below the custom layer; do not mask the road network. Labels may remain explicit overlays. Runtime order must be recorded. A custom layer appended blindly at the end does not prove correct composition.

Preserve incoming MapLibre depth range while rendering Three and restore owned GL mutations. Use `renderer.autoClear=false`, reset renderer state, and avoid touching stencil since tile clipping/extrusions own it. Installed Three r170 resetState does not call depthRange; still record the runtime depth range before/after. MapLibre marks state dirty and restores base state after render. Buildings use compatible LEQUAL/read-write range (`draw_fill_extrusion.ts:24-43`), including a depth prepass for translucent buildings; test opaque blockers first and production-opacity buildings separately.
